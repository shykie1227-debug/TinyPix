## 7. 最终交付：打包说明

### 7.1 为什么本机出不了 exe

实测：macOS 能 restore/build **除 App 外**的全部项目并能跑全部单测；App 项目在 XAML 编译阶段崩溃（`XamlCompiler output file … was not created`）。因此 exe 必须由 Windows 产出：GitHub Actions（`windows-latest`）或你的 Windows 机器。

### 7.2 打包命令（Windows 上执行）

```powershell
# ① 便携 ZIP（正式形态，含 FFmpeg 引擎）
pwsh ./build/publish-portable.ps1
#   → artifacts/TinyPix-4.0-Windows-x64-Portable.zip + .sha256

# ② 单文件 exe（可选形态）
pwsh ./build/Publish-SingleFile.ps1
#   → artifacts/TinyPix-single-file/TinyPix.exe + .sha256

# ③ 只要最简自包含文件夹（不打包 ZIP、不拉引擎）
pwsh ./build/Publish-WinExe.ps1
#   → artifacts/win-x64/TinyPix.exe
```

CI 路径：推送到 `main` 后 `build-exe.yml` 自动产出
`TinyPix-win-x64-portable` 与 `TinyPix-win-x64-single-file` 两个 artifact；也可在 Actions 页面 `Run workflow` 手动触发（`skip-ffmpeg` 可跳过引擎下载加速排错）。

### 7.3 产物路径与预期体积

| 产物 | 路径 | 预期体积 |
|---|---|---|
| 便携 ZIP | `artifacts/TinyPix-4.0-Windows-x64-Portable.zip` | ~350–420 MB（含 ~165 MB FFmpeg + ~110 MB 自包含运行时），压缩后约 150–200 MB |
| 单文件 exe | `artifacts/TinyPix-single-file/TinyPix.exe` | ~150–200 MB（内含 .NET 10 + WinAppSDK 运行时） |
| 同目录伴随 | `portable.flag`、`Config/`、`Engines/ffmpeg.exe` | ~170 MB |

> 伴随文件的原因不是偷懒，而是两条硬规则：`LOCAL_RULES.md` §2 要求 `portable.flag` 与 `Engines` 与 exe 同级；§3 只允许写入 `Config/Data/Cache/Logs`。单文件形态同样遵守。

### 7.4 干净机器验证步骤

1. 准备一台**未安装** .NET SDK、Visual Studio、Windows App Runtime、FFmpeg 的 Windows 10 22H2 或 Windows 11 x64 虚拟机。
2. 断开网络或防火墙阻断全部出站。
3. 便携形态：解压 ZIP → 双击 `TinyPix.exe` → 应直接打开窗口（首屏统一视频输出工作台）。
4. 单文件形态：把 `TinyPix.exe` + `portable.flag` + `Engines/ffmpeg.exe` 放同一目录 → 双击，首次启动会向临时目录释放依赖（略慢），之后正常。
5. 跑一个真任务：拖入一个 mp4 → 视频输出 → 导出。确认输出文件生成。
6. **源文件哈希校验**（`LOCAL_RULES.md` 验收门槛）：
   ```powershell
   Get-FileHash <源文件> -Algorithm SHA256   # 处理前后必须一致
   ```
7. 确认目录内只有 `Config/settings.json`、`Data/tinypix.db`、`Cache/`、`Logs/` 发生写入，且系统 `AppData` 与注册表无新增。
8. 若把整个目录设为只读再启动，应给出"请移动到可写位置"的提示，而不是静默改写别处。

### 8.2 仍未完成的验证：窗口启动

`prlctl exec` 是以 **SYSTEM / 非交互会话** 执行的（`UserInteractive=False`）。WinUI 的
`Microsoft.UI.Input.dll` 在无桌面会话下必然 fail-fast（0xC000027B / 0xC0000602）。
用一个**不含任何本项目 XAML 的最小 WinUI 应用**做对照，同样崩溃 → 证明这是执行环境问题，不是 TinyPix 的问题。

因此"双击后窗口出现"这一步必须由你在 VM 里手动双击确认（见 7.4）。

## 9. 待你确认的两项

1. **是否允许推送到 `origin/main` 触发 CI 出包**（不会 force、不会覆盖远端历史）。这是本机产出 exe 的唯一路径。
2. **WinAppSDK 版本不一致**（WinUI 2.2.1 / Runtime 2.2.0）是否现在统一——需要改 `Directory.Packages.props` 并刷新 8 个 lock 文件；不统一有构建失败风险，但改动面比本轮其他内容都大。
