## 1. 审计范围与用户目标

目标用户是在企业离线环境中快速处理本地媒体的普通办公用户和高频工具用户。产品必须解压即用、不安装、不联网、不写注册表、不修改原文件，并以少量稳定工作台覆盖常用媒体任务。

本轮复核覆盖：Pencil 当前画布、功能矩阵、交互规格、WinUI 控件映射、Core 工具目录、设置弹窗、视频剪辑时间轴、浅色/普通深色/High Contrast、工具箱范围和 Windows 交付门槛。

## 2. 最终产品决策

### 2.1 视频剪辑采用 LosslessCut-first 混合模型

推荐采用轻量工具逻辑，不复制专业 NLE 的复杂度：

- 以 LosslessCut 的非破坏、关键帧优先、片段保留/排除和快速导出为主模型。
- 参考 VidCutter 的低学习成本与片段排序。
- 借用 Shotcut 等专业工具的 J/K/L、I/O、分割、缩放和时间码输入，但不引入多轨、波纹/滚动编辑、转场、关键帧动画或工程文件。
- Avidemux 的 A/B 选区适合作为最小入出点逻辑，但不足以表达多个保留片段，因此不作为最终模型。

参考来源：

- LosslessCut 文档：https://github.com/mifi/lossless-cut/blob/master/docs/index.md
- Avidemux cutting 文档：https://avidemux.sourceforge.net/doc/en/cutting.xml.html
- Shotcut 快捷键：https://www.shotcut.com/howtos/keyboard-shortcuts/
- VidCutter：https://github.com/ozmartian/vidcutter

### 2.2 视频页面只保留三个顶层入口

1. 视频输出。
2. GIF 制作。
3. 视频剪辑。

“视频剪辑”只有一个 Page/ViewModel 壳层，内含“时间剪辑 / 合并拼接”模式。`video.trim`、`video.split`、`video.merge` 保持独立 Handler，避免业务逻辑耦合；不再为每个 Handler 建独立页面。

### 2.3 设置只有一个弹窗

- 右上角齿轮和 Ctrl+, 调用同一个命令。
- 只有一个 `SettingsDialog`、一个 `SettingsDialogViewModel`、一个 `SaveSettingsCommand`。
- 1200×800、900×600、High Contrast 画板只是同一视觉树的三种证据。
- 设置不复用媒体预览、右参数栏或任务队列，不再出现齿轮占位预览。
- Esc、关闭、取消不写入；保存先验证再原子写入，关闭后焦点返回触发控件。
- 清理缓存使用弹窗内行内确认，避免嵌套第二层模态。

### 2.4 工具箱范围

保留 PDF、OCR、二维码/条形码、屏幕录制、批量重命名副本、校验和、颜色/剪贴板和文件元数据。移除：

- ZIP/RAR/7z 等归档压缩与解压。
- 重复文件检测/删除。

视频、图片和 PDF 自身的媒体压缩能力继续保留。当前 Core 目录锁定为 50 个唯一工具 ID。

## 3. 真实视频剪辑操作逻辑

1. 添加文件：按钮、拖放和 Ctrl+O 进入同一校验流程；只记录路径，不复制源文件。
2. 准备预览：先显示可播放画面，再异步生成本地缩略图与波形；生成失败仍保留时间码编辑并说明降级原因。
3. 选择模式：默认“时间剪辑”；切换“合并拼接”后同一区域变为多文件有序片段轨。
4. 定位：拖动播放头、点击轨道、输入时间码、方向键、逐帧和关键帧定位保持同步。
5. 编辑：I/O 设置入出点，B 分割；Delete 执行可撤销的“排除/恢复”，不得表现为删除源内容。
6. 导出精度：
   - 关键帧优先：stream copy；显示用户请求边界、实际关键帧边界和差值，并按实际区间循环预览。
   - 精确到帧：明确显示“精确边界自动重编码”、预计耗时和预计体积。
7. 合并拼接：至少两个输入；拖动或键盘排序；逐项预览；预检分辨率、帧率、音轨和容器兼容性；必要时统一编码并补黑边/静音轨。
8. 输出预检：阻断全部片段被排除、区间非法、输出不可写、与源路径相同、磁盘不足和引擎缺失。
9. 入队：显示输入数、保留片段数、请求/实际时长、模式、输出目录和文件名。
10. 取消/结果：取消终止进程树并删除未完成临时文件；成功后重新探测输出，再提供打开文件/文件夹。

## 4. UI/UX 结论

已修复：

- 酸橙背景使用深色文字/图标。
- 普通深色主操作不再在不同页面间切换白底/黑底；统一 `action-primary` + `on-action-primary`，并以 `control-border` 保证按钮边界可辨。
- 设置页错误的齿轮预览、按钮裁切和媒体工作台复用已移除。
- 标准与紧凑时间轴均按同一源时间坐标系放置缩略图、波形、片段、I/O 和播放头；三条内容轨不再重叠，范围外、保留、已选、跳过均有非颜色文字或形状线索，空闲“分割”恢复中性按钮。
- 900×600 使用“更多”溢出入口，不再直接丢弃撤销、排除和缩放命令。
- High Contrast 设置遮罩已覆盖顶部导航；当前分类使用系统高亮配对，离线说明改为中性边框，三个开关显示开/关文字，保存按钮保留焦点矩形。
- 900×600 二维码生成已从错误的 PDF/媒体壳修正为文本输入、实时二维码预览、PNG/SVG 输出和 L/M/Q/H 离散纠错；预览、主操作与任务项统一使用二维码语义图标。
- 二维码预览区为 392×230，图标为 150×150，布局坐标 x=121、y=40，分别等于 `(392-150)/2` 与 `(230-150)/2`；主按钮、任务缩略图和导入按钮的图标+文字组合也按实际包围盒居中，不以肉眼估算。
- 全画布结构扫描未发现裁切、重叠；自动扫描的图标均为方形尺寸，未发现几何尺寸漂移。

仍需运行态验证：

- 125%/150% 显示缩放和 200% 文本缩放的真实图标视觉中心与基线。
- Hover、Pressed、Focused、Disabled、Loading 状态。
- High Contrast 选中项的勾选/“已选择”非颜色线索。
- 当前 Pencil 预览已使用本地生成的真实二维码 PNG，而不是二维码图标占位；它证明设计态内容与输入一致，但尚未用发行版 ZXing.Net 独立解码，真实 PNG/SVG、纠错级别和扫码结果仍必须在 Windows 原型中验证。
- 鼠标命中、拖动、播放同步、焦点陷阱、关闭设置后的焦点恢复和 Narrator。

## 5. 独立角色复核

产品经理结论：单轨保留片段模型适合轻量离线产品；必须显示请求边界和实际关键帧边界，不能用静态规格替代真实输出验证。

UI/UX 设计结论：设置应为同一响应式弹窗；主要风险是命令语义、紧凑版命令可达性、深色主按钮边界和高对比非颜色状态。上述静态问题已纳入当前设计，运行态问题进入 Windows 门禁。

项目经理结论：当前不能宣布 UI 冻结、WinUI 完成或 Portable 可交付。下一里程碑必须是事实源一致性验证，然后在 Windows VM 执行可丢弃原型。

## 6. 交付门槛

### M0 当前事实源收口

- 功能矩阵、Core 目录、Pencil、导出图和文档统一为 50 个工具。
- 移除 ZIP、重复文件检测和独立视频合并页面/导出。
- 设置锁定为单弹窗；视频剪辑锁定为单工作台双模式。
- Core、设计合同、布局检查和 Git diff 检查通过。

### M1 Windows VM 可丢弃原型

- Unpackaged/self-contained 启动。
- 唯一设置弹窗的焦点限制、取消/保存和焦点恢复。
- 单轨时间轴的播放、拖动、I/O、分割、排除/恢复、撤销/重做和溢出菜单。
- FFmpeg 缩略图、波形、关键帧边界、精确重编码、进度、取消和异常退出。
- 900×600、1200×800、100%/125%/150%、Light/Dark/High Contrast。
- `portable.flag`、不可写目录阻断、断网运行和无主动注册表写入。

原型代码可丢弃，只保留报告和证据；通过后再进入正式 WinUI Shell。

### M2 正式实现

先实现 App Shell、共享组件、唯一 SettingsDialog 和视频剪辑共享工作台，再按完整纵向流程接入 Handler。每个工具必须同时具备真实输入、预览、参数、队列、取消、错误、输出和源文件 SHA-256 不变证据。

## 7. 当前证据限制

Pencil 证明的是结构、视觉与静态状态；Core 测试证明的是目录和业务合同。两者都不能证明 Windows 原生控件、FFmpeg 真实媒体输出或 Portable 部署已经工作。完成声明必须等待 Windows VM 的新证据。
