# TinyPix 4.0 功能矩阵

> 状态：实施冻结稿
> 平台：Windows 10 22H2、Windows 11 x64
> 技术基线：C# / .NET 10、WinUI 3、Unpackaged self-contained Windows x64 便携版
> 核验日期：2026-07-17

## 1. 产品与数据底线

1. TinyPix 运行时完全离线：无账号、遥测、云 API、更新检查、远程资产、运行时下载、登录、上传或外部发送能力。文档及证件照模板保存的官方 URL 只可离线显示和复制；应用不得打开浏览器或发起请求。
2. 发行物解压即用；不得安装、写注册表、注册文件关联、创建服务或计划任务，也不得要求管理员权限。
3. 首次启动进入“视频工具 > 视频输出”。所有工具归入八类模板：转换/压缩、时间线编辑、图像编辑、智能证件照、PDF 页面管理、OCR/二维码识别、生成器/文件工具、设置/历史/缓存。
4. 添加、拖入、预览、识别和处理只读取源文件；移除列表项只移除路径引用。任何工具都不得覆盖、删除、移动、改名或回写源文件。`file.rename` 也只能在输出目录创建重命名副本。
5. 正式结果只写用户在入队前确认的输出目录；不得把结果静默写回源目录。写入采用“同目录临时文件 → 完成校验 → 原子改名”的方式；取消或失败只删除该任务未完成的临时文件。
6. 任一必需路径不可写、空间不足或不在允许边界内时，任务不得入队；不得降级写入 `%AppData%`、`%LocalAppData%`、系统临时目录、用户文档或注册表。

### 1.1 便携目录与唯一写入白名单

设解压目录为 `<Root>`。除用户确认的正式输出外，运行时可变数据只能写入下表；引擎、模型、许可证和程序文件只读。

| 路径 | 唯一允许内容 | 保留与清理 | 不可写时 |
|---|---|---|---|
| `<Root>/Config/settings.json` | 输出目录、主题、减少动态效果、缓存上限、最近工具；原子写入 | 用户“恢复默认”时重建；不保存媒体内容 | 设置不落盘，所有处理任务阻止并提示重新解压到可写目录 |
| `<Root>/Data/tinypix.db` | Microsoft.Data.Sqlite 保存最近路径、任务参数摘要、状态、输出路径和时间；最近文件最多 200，历史最多 1000 | 清空历史只删数据库记录，不删源文件、缓存或输出 | 历史与任务持久化不可用，所有处理任务阻止 |
| `<Root>/Cache/Preview` | 图片预览 | 缓存总上限计入 5 GiB；按最后访问时间淘汰非活动项 | 需要预览的任务阻止 |
| `<Root>/Cache/Video` | 视频缩略图、波形 | 同上 | 需要视频预览或波形的任务阻止 |
| `<Root>/Cache/PDF` | PDF 页缩略图和预览位图 | 同上；活动页面不得清理 | PDF 工具阻止 |
| `<Root>/Cache/OCR` | OCR 逐页中间图 | 每页识别落盘后立即删除；异常退出遗留项下次启动清理 | OCR 工具阻止 |
| `<Root>/Cache/Temp` | 当前任务未完成的临时输出 | 成功原子提交后删除；取消/失败删除本任务项 | 所有修改型任务阻止 |
| `<Root>/Logs` | 按日技术日志；记录任务 ID、阶段和错误码，不记录媒体内容、OCR 文本或文件哈希 | 保留 14 天且总量不超过 20 MiB，先删最旧文件 | 所有处理任务阻止；只允许进入诊断页 |
| 用户确认的输出目录 | 用户明确执行后产生的正式结果 | 仅用户自行管理；清缓存/历史绝不删除 | 当前任务阻止并聚焦“选择可写位置” |

### 1.2 命名、冲突与序列规则

- 普通单文件、文件夹及重命名副本冲突：保留完整扩展名，在文件名末尾追加半角空格和 `(<n>)`，从 ` (1)` 起选最小可用正整数。例如 `报告.mp4` → `报告 (1).mp4`。已有 `报告 (1).mp4` 时继续为 `报告 (2).mp4`。
- 多结果序列：固定三位编号 `_001`、`_002`……，编号按输出顺序递增，不因失败复用。例如 `视频_帧_001.png`。序列文件本身冲突时再应用普通规则，例如 `视频_帧_001 (1).png`。
- 默认冲突策略只有“自动追加编号”；“覆盖”不属于 TinyPix 4.0 功能范围。冲突必须在入队前完成预检并显示最终路径。

### 1.3 队列、成功与通用错误

- 媒体重任务并发固定为 1；轻量文件任务并发固定为 2；PDF 栅格化和 OCR worker 固定为 1；MODNet session 固定为 1。单项失败不阻断其余任务。
- 固定状态：草稿、等待、执行中、取消中、成功、失败、已中断、已取消。不提供引擎无法兑现的“暂停”。
- 成功必须验证正式输出存在、大小大于 0 且可重新打开；显示成功/失败数量、耗时、输出路径和“打开文件/打开文件夹/再次处理”。
- 通用阻止错误：输入不存在、类型不支持、文件损坏、参数越界、引擎/模型缺失或哈希不符、输出不可写、磁盘不足、文件被占用、便携数据目录不可写。错误必须指明文件、原因和恢复动作。
- 支持文件添加后必须显示真实本地预览；原生预览失败时显示本地生成的缩略图/页面图及原因，不得退回空拖放状态。

### 2.1 FFmpeg 与 H.264 强制门禁

- 每次正式构建必须归档 `ffmpeg -version`、`-buildconf`、`-L`、`-encoders`、`-filters`。出现 `enable-gpl`、`enable-nonfree`、`enable-version3`、`libx264`、`libx265`、`libfdk_aac` 或 E2 禁止项即构建失败。
- 所有 H.264 输出优先且只使用 Windows Media Foundation 编码能力；任务预检找不到兼容 H.264 编码器时返回“此电脑缺少可用的 Windows H.264 编码器”，禁用开始按钮。不得偷偷下载、捆绑或切换至 GPL/nonfree 编码器。
- FFmpeg 滤镜若不在最终 LGPL 构建清单中，对应参数在引擎自检中标为不可用并阻止任务；不得为补齐功能启用 GPL 滤镜。图片效果优先由 E3/E4 实现。

### 2.2 PDF 签名统一规则

- 添加 PDF 时由 PdfPig 结构读取检查签名字典、`/FT /Sig` 和 `/ByteRange`；任一命中即标记“包含数字签名”。检测失败按 PDF 不可安全修改处理。
- `pdf.merge`、`pdf.split`、`pdf.reorder`、`pdf.rotate`、`pdf.watermark`、`pdf.compress` 以及 `file.metadata` 的 PDF 清理都属于修改型工具。签名 PDF 在入队前硬阻止，不提供“仍然继续”；提示“修改副本会使原签名失效，请改用只读导出”。
- `pdf.to-image`、`ocr.pdf` 和信息查看是只读操作，可以处理签名 PDF，但必须提示导出的图片/文本不携带、不验证也不代表原数字签名。
- TinyPix 4.0 不接收密码、不解密 PDF；加密 PDF 在添加阶段阻止。PDFsharp/PdfPig 只编辑/读取，所有栅格化统一走 E7，不允许 Windows.Data.Pdf 或 WebView fallback。
