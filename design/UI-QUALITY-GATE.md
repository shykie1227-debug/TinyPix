# TinyPix 4.0 UI/UX 质量门禁

状态：静态 UI 设计冻结已通过；Windows 运行态门禁待执行
日期：2026-07-19

## 1. 责任原则

任何“最优、完成、冻结、可用”结论必须有当前证据。经验只能产生待验证假设，不能代替用户任务、真实媒体、Windows 控件、输出文件和无障碍验证。

以下任一项失败，UI 不冻结、正式业务页面不放行：

1. 功能矩阵、Pencil、WinUI 映射、Core 工具目录和导出图不一致。
2. 同一功能出现重复入口、重复页面、重复 ViewModel 或重复保存逻辑。
3. 文字缺失、裁切、错误占位、图标语义错误、按钮角色/尺寸无理由漂移。
4. Hover、Pressed、Focused、Disabled、Loading 或错误/空/成功状态缺失。
5. 鼠标、键盘、触摸命中和 Narrator 不能完成同一核心流程。
6. UI 参数组合可形成业务矛盾，或 UI 显示与实际 FFmpeg/PDF/OCR 输出不一致。
7. 仅凭颜色表达选中、成功、失败、排除或高对比状态。
8. 时间轴未按源时间戳换算到同一源时间坐标系，或缩略图、波形和片段轨不得重叠的合同被破坏。
9. 二维码生成使用播放图标、媒体播放器或连续质量滑块，而不是实时二维码预览与 L/M/Q/H 离散单选。

## 2. 唯一组件与页面规则

- 设置：一个入口命令、一个 `SettingsDialog`、一个 ViewModel、一个保存命令；标准/紧凑/High Contrast 仅是同一组件状态。
- 视频：顶层只有视频输出、GIF 制作、视频剪辑；时间剪辑/分割/合并拼接共用一个视频剪辑工作台，Handler 独立。
- 主按钮：统一 `action-primary` / `on-action-primary` / `control-border`；页面不得另建颜色。
- 图标：同一动作只用一个语义图标；Pencil 层名必须描述实际用途，不以 `playIcon` 命名图片、人物、OCR 或二维码预览。
- 900×600：命令可进入原生溢出菜单，但不得消失或只能依赖快捷键。
- High Contrast 设置：遮罩覆盖顶部导航在内的完整 `XamlRoot`；选中项使用 `Highlight` / `HighlightText`，中性离线信息使用 `Window` / `WindowText`，开关含开/关文字并保留系统焦点矩形。
- 视频时间轴：所有可视元素按源时间戳换算；入点、出点和播放头语义不同，范围外有文字，空闲态不得高亮“分割”。
- 二维码生成：输入、预览、参数、主操作和任务必须语义一致；不得使用播放图标或连续质量滑块。

## 4. Windows 运行态检查矩阵

每个代表流程必须在 1200×800 与 900×600、100%/125%/150%、Light/Dark/High Contrast 下执行：

1. 文本：完整、可换行、无省略关键信息；200% 文本缩放仍可达。
2. 按钮：同角色同高度/内边距；紧凑差异必须由 VisualState 明确；命中区至少 44×44。
3. 图标：语义、尺寸、视觉中心、文字基线、前景和 Tooltip/Automation Name 一致。
4. 焦点：Tab/F6 顺序正确；焦点可见；Dialog 焦点陷阱和关闭后恢复正确。
5. 视频剪辑：缩略图/波形/播放头同步；I/O、分割、排除/恢复、撤销、溢出命令和导出结果一致。
6. 设置：取消不写入，非法值聚焦首错，保存原子写入；无嵌套模态。
7. 输出：请求/实际关键帧边界可见；精确模式误差不超过一帧；源文件哈希不变。
8. 异常：只读目录、磁盘不足、损坏媒体、引擎缺失、取消和失败均有明确恢复动作。
